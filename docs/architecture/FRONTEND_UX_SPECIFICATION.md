# 前端与 UX 规格

## 1. 信息架构

| 路由 | 目的 | 初始渲染 |
|---|---|---|
| `/` | 项目简介和两个应用入口 | Server Component |
| `/estimator` | 单套房产估价 | Server shell + Client form |
| `/estimator/history` | 历史估价 | Client Component |
| `/estimator/compare` | 多套横向比较 | Client Component |
| `/market` | 市场摘要、图表、筛选表格 | Server initial data + Client filters |
| `/market/what-if` | 调整特征并比较预测 | Client Component |

## 2. 共享布局

- 顶部品牌和主导航。
- 当前应用有可见 active 状态并设置 `aria-current="page"`。
- 页面主内容使用 `<main>`，提供跳过导航链接。
- 共享响应式容器、颜色、排版、间距和卡片规范。
- 全局错误边界不吞掉页面级错误详情。

## 3. Estimator

### 表单字段

全部字段显示人类可读标签和单位：平方英尺、卧室数、浴室数、建造年份、地块面积、到市中心距离、学校评分。

### 交互

- 首次进入提供合理示例值，但必须清楚标记为示例。
- 提交时禁用重复提交并显示进度。
- 字段错误就近显示，顶部提供错误摘要。
- 成功后显示预测价格、输入摘要、模型版本和范围外警告。
- 图表可以展示预测价格与历史记录或选中比较对象。

### 历史 schema

`localStorage` key 使用版本化名称，例如 `property-estimates:v1`。每条记录包含本地 UUID、时间、7 个输入、预测价格和模型版本。限制最大条数，提供清空确认。

## 4. Compare

- 可选择 2~4 条历史记录。
- 行表示字段，列表示房产，避免横向空间不足时强行挤压。
- 移动端改为纵向卡片或可访问的受控横向区域。
- 明确突出最高/最低预测，但不能只依靠颜色表达。

## 5. Market Dashboard

### 摘要卡

- 记录数。
- 平均/中位价格。
- 最低/最高价格。
- 平均面积。

### 图表

- 价格分布。
- 面积与价格关系。
- 按卧室数或建造年份分段统计。

图表必须有标题、轴标签、单位、tooltip 和文字替代摘要；不要堆叠无法解释的装饰图表。

### 筛选

- 价格、面积、卧室、浴室、年份、学校评分、距离范围。
- 有“应用”和“重置”，URL query 可选但推荐，以便刷新和分享状态。
- 空结果显示当前筛选条件和重置入口。

### What-if

- 以选中数据行或示例房产为基准。
- 用户修改一个或多个字段。
- 展示原预测、新预测、绝对差和百分比差。
- 明确说明这不是因果推断。

## 6. 导出

- CSV：当前筛选后的原始行，包含列头并保持数值类型语义。
- PDF：标题、生成时间、筛选条件、摘要指标和主要表格/图表摘要。
- 文件名包含日期和筛选上下文，生成失败时不得下载空文件。

## 7. 状态设计

每个数据区域必须定义：

- 初始 loading skeleton。
- 成功且有数据。
- 成功但空数据。
- 验证失败。
- 后端不可用/超时。
- 重试中。

## 8. 可访问性与响应式

- 所有输入都有显式 label。
- 错误和成功消息使用合适的 live region。
- 焦点可见，模态框正确管理焦点。
- 色彩对比符合 WCAG AA 目标。
- 360px 宽度下主要流程可用；1280px 桌面布局充分利用空间。
- 动画尊重 `prefers-reduced-motion`。
