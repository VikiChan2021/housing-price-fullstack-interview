# 安全与可靠性

## 安全边界

- 本项目没有认证，但仍将所有外部输入视为不可信。
- 浏览器只访问 Next.js；内部服务仅在 Compose 网络暴露，宿主端口用于面试调试。
- 不在 `NEXT_PUBLIC_*` 或客户端 bundle 中放置服务密钥。
- `.env` 不提交；`.env.example` 只包含无秘密的占位配置。
- CSV/PDF 导出需要防止公式注入和不可信文本进入文件。

## 输入和输出

- Python 使用 Pydantic，Java 使用 Bean Validation。
- 拒绝 NaN、Infinity、空批次和超大批次。
- 建议批量预测上限 100 条；超过返回 413 或 422。
- 错误响应不包含堆栈、主机路径或模型二进制信息。
- 金额以 JSON number 返回，展示格式由前端处理。

## 下游调用

- Estimator/Market 调用 ML API 必须设置连接与总超时。
- 只对幂等读取或明确安全的请求做有限重试；预测 POST 默认不盲目多次重试。
- Java 缓存键必须基于规范化筛选参数，不能忽略任一过滤条件。
- Caffeine 设置最大条目和 TTL，避免无界内存增长。

## 健康检查

- liveness：进程能够响应。
- readiness：关键依赖已加载，例如模型或 CSV。
- 原题要求的 `/health` 至少返回总体状态；可额外提供 `/ready`，但不能用额外端点替代 `/health`。

## 日志

- JSON 或稳定结构日志。
- 字段包含时间、级别、服务、请求 ID、路径、状态和耗时。
- 不记录完整批量请求或未来可能出现的敏感信息。
- 模型预测日志记录模型版本和批量大小，不记录虚构准确率。

## 失败注入验收

至少演示并测试：

1. ML API 停止后 Estimator 显示可重试错误。
2. 非法表单返回字段级 422。
3. Market 空筛选结果不是服务异常。
4. 模型文件损坏时 readiness 失败。

## 生产边界

本设计为面试演示级。没有完成鉴权、限流、WAF、集中日志、备份、高可用和生产监控前，不得声明为生产就绪。
